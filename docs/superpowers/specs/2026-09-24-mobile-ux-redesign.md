**작성일:** 2026-09-24
**Model:** GPT-6 Astra (분석·설계), 코드 근거 확인 gpt-5.6-sol / high 2명
**상태:** 2026-09-25 사용자 요청으로 구현 반영 후, 모바일 견적 내비게이션과 저장 바를 다시 정정했다. 본문의 관측값은 변경 전 기록이며 기존 구현/검증 결과는 [검증 기록](../reviews/2026-09-24-mobile-ux-verification.md)에 구분한다. 최신 sticky 카테고리 버튼·Review 상시 표시·직접 Save & Sync 정정도 로컬 코드·브라우저 검증을 완료했다. 검증 기록의 후속 정정 절을 참고한다. 이번 구현·검증 모델은 최신 지시에 따라 모두 gpt-6-astra다.
**실행 문서:** [순차 변경·검증 계획](../plans/2026-09-24-mobile-ux-redesign.md)

## 1. 결론과 이번 개선의 목표

현재 앱은 16px 모바일 입력 글자, 44px 주요 버튼, 견적 하단 저장 바 등 기본 반응형 규칙을 갖추고 있다. 가장 큰 불편은 **입력·설명·통계·관리 기능을 같은 중요도로 길게 펼쳐 놓는 구조**다. 버튼과 입력칸 크기를 줄이기보다, 현재 작업을 선택하고 필요한 항목 하나만 편집하도록 바꾼다.

개선 우선순위는 다음과 같다.

1. 견적에서 기본정보·자재·공개 견적·합계를 자유롭게 바로 이동한다.
2. 반복되는 자재·공개 항목은 요약으로 읽고 선택한 항목만 편집한다.
3. 검색과 핵심 금액을 첫 화면으로 올리고, 추가·CSV·설정 등 관리 기능을 접는다.
4. 색상에 일정한 의미를 주고, 작은 글자의 대비와 상태 라벨을 보강한다.
5. 같은 데이터·저장·권한 규칙을 유지하면서 실제 모바일 작업 흐름을 검증한다.

이 문서는 UI 구현 범위의 제안과 완료 기준이다. DB, 계산 공식, 접근 권한, Jobber 동기화 계약, 기존 운영 배포 선행 조건을 변경하는 승인이 아니다. `docs/DECISIONS.md`와 현행 `docs/UI-DESIGN-SYSTEM.md`는 그대로 유지하며, 구현된 범위만 실행 마지막 단계에서 현행 UI 문서에 반영한다.

## 2. 관측 범위와 한계

- 로그인된 운영 앱의 Inventory, New/Edit Quote, Overview, 견적 상세, Settings Labour/Material/Area, Jobs 달력과 비용 상세를 읽기 전용으로 관찰했다.
- Chrome CSS viewport 390×844에서 측정했다. 데스크톱 스크롤바로 실제 콘텐츠 폭은 375px였다. Jobs만 360×800을 추가 확인했다. 실제 iPhone/Safari/PWA·가상 키보드·터치·스크린리더 검증은 아니다.
- 수정 견적은 공개 항목 19개·자재 7개인 샘플 하나다. 전체 사용자의 평균 견적을 뜻하지 않는다. 비용 상세는 비용 0개 샘플이므로 긴 비용 목록 문제를 확정하지 않는다.
- Save, Sync, Fetch, Refresh, Add, Delete를 실행하지 않았다. 입력 복구·저장·옵션 생성은 코드 근거이며 실제 동작 검증은 후속 구현 단계에 남긴다.
- 최초 코드 분석은 `c20e1ac`, 실행 계획의 재확인 기준은 로컬 `main`의 `e4970ad`다. 운영 화면과 해당 소스의 배포 버전 일치를 전제로 삼지 않는다.
- 원본 관측 보고서와 검수한 PNG 14장은 로컬 `.superpowers/audits/2026-09-24-mobile-ux/report.md`에 있다. 고객 정보가 포함될 수 있는 캡처는 공용 문서에 복사하지 않는다.

## 4. 모바일 견적의 목표 구조

앱의 기존 영문 표기를 유지한다. `≤720px`에서 sticky `Details` / `Work & materials` / `Public quote` 버튼으로 현재 입력 카테고리를 바꾼다. 세 버튼은 360px에서도 가로 overflow 없이 한 줄에 맞고 각각 44px 이상의 터치 영역을 제공한다. Review는 선택 카테고리가 아니라 현재 입력 영역 다음의 마지막 섹션으로 항상 표시한다. 강제 순서나 다음 단계 완료 조건을 두지 않는다.

```text
기존 역할별 앱 메뉴
페이지 제목 / 필요한 상태
sticky 카테고리: [Details] [Work & materials] [Public quote]

현재 영역 내용
  Area 선택 + 다른 Area의 항목 개수
  자재 A | Area · 수량 × 단가 · 금액    Edit
  자재 B | 현재 편집 필드
  자재 C | Area · 수량 × 단가 · 금액    Edit
  Options (개수 · 별도 금액)            Open

Review (현재 입력 영역 아래 항상 마지막)
  Final subtotal / GST / Inc GST / Options

고정 하단: Final subtotal / Inc GST | Save | Save & Sync
           금액 선택 → Review
```

| 영역 | 포함 내용 | 기본 표시 |
|---|---|---|
| Details | 고객·주소·Jobber 연결/기본정보 | 새 견적 기본 진입 |
| Work & materials | Main Materials, Area, Options와 각 자재 | 수정 견적 기본 진입 |
| Public quote | 고객에게 표시할 항목·설명·세금/표시 상태·템플릿 | 요약 목록 |
| Review | Area별 공식 비교·수동 Low/High·Main 합계·Options 별도 합계·메모·동기화 미리보기 | 현재 입력 영역 아래 항상 마지막, 금액 우선·상세 접힘 |

### 견적 상세 요구사항

- **R01 — 단일 데이터 소유권:** `QuoteForm`이 기존 견적 상태를 계속 소유한다. 편집기는 기존 콜백으로 즉시 부모 값을 갱신한다. 화면 전환이 데이터 저장이나 취소를 뜻하지 않는다.
- **R02 — UI 상태 분리:** 영역, 열린 자재/공개 행/옵션, 현재 Area, 포커스 대상은 presentation state다. payload·dirty 비교·새 draft 저장값에 넣지 않는다. 기존 draft의 `options[].isExpanded`는 호환 읽기를 지원하되 도메인 변경으로 비교하지 않는다.
- **R03 — 단일 입력 트리:** 모바일·데스크톱 폼을 각각 복제하지 않는다. 각 입력·radio·자동완성은 한 인스턴스다. 데스크톱에서는 모든 섹션을 함께 보이게 하고, 모바일에서는 세 입력 카테고리 중 선택한 하나와 그 아래 Review를 보인다. 숨긴 두 입력 영역은 Tab 순서와 스크린리더에서 제외한다. 세 카테고리 버튼은 현재 선택을 접근성 상태로 전달하고 360px에서 가로 overflow 없이 44px 이상이어야 한다. Details의 Fetch 아래 `Products & pricing` shortcut은 기존 입력과 draft를 유지한 채 Public quote만 선택하며 Fetch/Refresh나 payload 변경을 일으키지 않는다.
- **R04 — 자재 요약:** 이름, Area, 수량×RRP, 자재 금액, 작업일/노무 요약을 남긴다. Main에서 한 행, 열린 Option 안에서 한 행만 편집한다. 이름과 Area는 전폭, `Qty/RRP`와 `Working Days/Labour per Day`는 값이 잘리지 않을 때 2열이다. 메모는 내용 유무와 요약을 보여주고 필요할 때 연다.
- **R05 — Area와 정렬:** 다른 Area는 개수·이동 버튼으로 요약한다. 미배정 경고와 해결 동선을 유지한다. drag와 위/아래 이동을 지원하고 기존 functional reorder updater를 사용한다. 필터 밖 행의 순서·값을 보존한다.
- **R06 — 공개 항목:** 이름·종류·금액 또는 text 표시·taxable/client-visible 상태를 요약한다. 선택한 행만 편집하며 이름/설명은 넓게 쓴다. 이 구조와 함께 목록의 `72vh` 내부 스크롤을 제거한다. 긴 설명 입력의 내부 스크롤은 허용하지만 기본 목록에는 설명 요약만 둔다. add/edit/remove/reorder/template 모두 기존 `JobberQuoteLinesChange` 경계를 지나 삭제된 Jobber ID 추적을 유지한다.
- **R07 — 공식과 옵션:** 다섯 공식을 간결한 비교 행으로 보여주고 기존 수동 Low/High 선택을 보존한다. 둘 다 선택한 행에는 두 라벨을 표시한다. 실제 Low 금액이 High보다 커도 자동 교환·정렬·오류 처리를 추가하지 않는다. Main의 세 Area별 선택과 Option 하나당 기존 한 쌍의 선택을 구분한다. Options는 모바일에서 하나씩 열며 Main 합계에 포함하지 않는다.
- **R08 — 저장과 오류:** 기존 하단 저장 바를 유지한다. Save는 로컬 저장이며 Save & Sync는 More 메뉴 없이 바로 옆의 별도 명시 동작이다. 검증 오류가 숨겨진 행에 있으면 해당 입력 카테고리→옵션→Area→행을 열고 필드에 포커스한다. 경로 없는 서버/충돌 오류나 하단 금액 이동은 항상 보이는 Review로 스크롤·포커스하되 현재 입력 카테고리를 바꾸거나 숨기지 않는다. sticky 상단 카테고리와 하단 바가 이동한 필드를 가리지 않도록 scroll margin을 둔다. 성공 후에만 draft 삭제·이동하며 실패값, pending lock, 복사 진행 잠금, sync 미리보기와 fail-closed 동작을 유지한다.

## 5. 다른 화면의 변경 명세

- **R09 — 공통 셸:** 기존 admin 5개 / supervisor 2개 목적지, 활성 메뉴, route progress, sidebar 전환을 유지한다. 새 하단 전역 메뉴를 견적 저장 바와 겹쳐 추가하지 않는다. 360px에서 메뉴가 안 맞으면 줄 배치와 라벨을 조정하되 목적지를 숨기거나 글자를 10px로 되돌리지 않는다. 본문 제목·긴 도움말·보조 액션 중복을 줄인다.
- **R10 — Overview:** 검색/월 필터를 KPI보다 앞에 두고 KPI는 모바일 2×2다. 금액 기준을 명시한다. KPI는 `finalTotal`/inc GST, 견적 행은 기존 `subtotal`/ex GST다. 최근 최대 100개 기반 값에 전체 DB 통계처럼 보이는 “all time” 표현을 쓰지 않는다. 서버 집계 신설·조회 범위 확대는 이번 범위가 아니다.
- **R11 — 견적 상세:** 첫 화면에 Final subtotal(Ex GST), GST, Inc GST 및 Options 별도 표시를 둔다. Read-only 표기와 Edit 등 액션을 보존한다. 고객/메타데이터·긴 설명·자재는 요약/접힘으로 정리한다. 기존 8행 더보기와 Jobber 동기화 상태·복구 동작을 없애지 않는다.
- **R12 — Inventory:** 검색을 먼저, 필터를 가능한 2열로, CSV는 보조 메뉴로 배치한다. Add는 현재 접힘 동작을 유지한다. 접힌 카드는 **Name, Category, Size/Serial, Colour**를 계속 보여주되 짧은 인라인 배치로 압축한다. 비어 있는 Colour의 `-`도 보존한다. 수량/상태는 함께 읽히게 한다. admin 편집과 supervisor의 수량·사용일·사용위치·상태 변경 경계를 유지한다.
- **R13 — Settings/Areas:** 후속 사용자 요청에 따라 모바일 설정 선택기를 5개 직접 버튼으로 바꾼다. 3+2 두 줄, 48px 이상, 라벨 줄바꿈과 파란 선택 상태를 사용한다. 페이지 상단의 중복 Inventory 링크만 제거하고 전역 메뉴는 유지한다. Add 폼은 닫힌 상태에서 시작하고 실패 시 값과 열림을 유지한다. Material 등 넓은 표는 `≤720px`에서 요약 행과 선택 편집 카드, 그 위 폭에서는 현재 표를 사용한다. Areas는 scope/검색으로 줄이되 목록 필터와 새 Area의 scope 입력을 다른 상태로 둔다. 기존 tab key·lazy loading·retry·25행 pagination을 유지한다.
- **R14 — Jobs/비용:** 모바일 달력은 날짜와 작업 개수, 아래 agenda는 선택 날짜의 작업번호·작업명·상태·상세 링크를 보여준다. 날짜 셀 안 모든 작업 링크를 억지로 44px 폭으로 만들지 않는다. 셀은 최소 24px 폭/44px 높이, 핵심 agenda 액션은 44px를 목표로 한다. 기존 방문 일정의 Sydney 날짜 변환·기간 포함·같은 날 중복 제거를 공유한다. 추가 API 요청이나 접근 범위 확대 없이 받은 데이터로 구성한다. 비용 요약은 Estimated/Actual과 금액 기준을 문자로 명시한다.

## 6. 색상·서체·간격 기준

색상은 섹션마다 임의로 다르게 칠하는 용도로 쓰지 않는다. 흰 입력 면, 중립 요약 면, 파란 주요 동작·현재 위치를 기본으로 하고 상태는 작은 배지·아이콘·라벨로 구분한다.

| 용도 / 제안 토큰 | 글자 | 배경 | 계산 대비비(약) | 적용 규칙 |
|---|---|---|---:|---|
| 보조 텍스트 `--secondary-text` | `#5F6F84` | `#FFFFFF` | 5.13:1 | 날짜·메타데이터. 기존 `#94A3B8`/white 약 2.56 개선 |
| Low/성공 `--lo-text`, `--success-text` | `#087653` | `#E7F7F0` | 5.09:1 | Low와 Success 각각 문구 필수 |
| High `--hi-text` | `#5B3CC4` | `#EFEAFF` | 6.19:1 | High 라벨과 선택 표시 |
| 경고 `--warning-text` | `#8A5A14` | `#FFF8E8` | 5.58:1 | 미배정·주의. 단순히 Low/High 둘 다 선택된 상태에 사용 금지 |
| 오류 `--danger-text` | `#B42318` | `#FDEEEE` | 5.84:1 | 오류 문구와 해결 동선 |
| 선택/정보 `--primary-strong` | `#0756BB` | `#E8F2FF` | 6.08:1 | 현재 영역·선택·정보 |

위 값은 지정한 두 색의 계산값이며 전체 앱 접근성 통과 판정이 아니다. 기존 밝은 색은 장식·아이콘에 남길 수 있다. 실제 hover/focus/disabled·표면 조합을 별도로 확인한다. 토큰 이름이 기존에 있으면 중복하지 말고 역할을 통합한다.

- **R15 — 대비:** 일반 텍스트 4.5:1, 큰 텍스트 3:1 기준. 상태는 색상과 함께 문구·아이콘을 사용한다. [W3C 텍스트 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [색상만으로 의미를 전달하지 않는 기준](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).
- **R16 — 크기:** 모바일 입력 16px 이상, 핵심 클릭 영역 44px 이상을 유지한다. 본문/행 이름 14–16px, 메타데이터 12–13px, 주요 금액 22–28px를 기준으로 삼는다. 44px는 프로젝트 목표이며 WCAG 2.2 AA 최소 target 24px 및 간격 예외와 구분한다. [W3C target 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).
- **R17 — 반응형:** shell은 `≤1023.98px` 모바일/`≥1024px` sidebar, 좁은 편집·Inventory 카드 전환은 `≤720px`다. 768px는 모바일 shell + 표 조합이 정상이다. 기존 `≤1080px` 레이아웃도 별도로 확인한다. 문서 가로 overflow는 0이어야 하며 필요한 표 내부 스크롤은 허용한다.
- **R18 — 읽기/입력 흐름:** 요약 카드는 짧은 내용 기준 80–112px를 목표로 하되 긴 이름·글자 확대는 자연스럽게 늘어난다. 고정 높이로 자르지 않는다. 섹션 간 16–24px, 카드 내부 12–16px를 기준으로 중복 여백을 줄인다. safe-area와 키보드에 저장/현재 필드가 가려지지 않아야 한다.

## 7. 변경하지 않을 핵심 규칙

1. `decimal.js`, 기존 공식 5개, pricing_settings, 수동 min/max 평균, 금액 스냅샷, Main GST 10%, Options Ex GST 별도 합계를 보존한다.
2. QuoteForm 데이터·local draft 복구·300ms 저장·pagehide flush·저장 충돌/version 검사·삭제 추적·Jobber sync 미리보기를 보존한다.
3. 기존 Server Action·DB schema·RLS·role guard를 변경하지 않는다. supervisor에게 admin 필드나 데이터가 렌더링되지 않게 한다.
4. 비용 원가나 실제 고객 데이터를 로그·테스트 캡처·공용 문서에 추가하지 않는다. 합성 fixture를 사용한다.
5. 새 외부 의존성, 가상 목록, 새 서버 집계, 새 일정 조회, 새 동기화 기능, 운영 DB/환경변수/배포 변경을 포함하지 않는다.
