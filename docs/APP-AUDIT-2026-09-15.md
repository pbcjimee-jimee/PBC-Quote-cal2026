### 2. P0-02 — Jobber 중복 실행 방지와 실패 후 복구

**영향:** 외부 line 생성 직후 로컬 ID 기록 전에 프로세스가 종료되면 재시도가 중복 생성할 수 있다. 두 탭/관리자의 같은 quote/version Retry도 동시에 외부 mutation을 실행할 수 있다. 결과 저장의 version 검사는 작업별 중복 실행권을 제어하지 않는다.

**로컬 구현:** 불변 operation outbox, 5분 lease의 단일 claim, mutation별 journal, 완전한 completion marker, read-only reconciliation, quote identity/version 기반 Retry/Check UI를 연결했다. 만료 status read도 claim 없이 reconciliation-required로 전환하고 token·raw error를 노출하지 않는다.

**final review 후속:** Important 2건과 Minor 1건을 로컬에서 수정했다. 재대조 실패 종류를 고정 안전 문구로 구분하고 success만 `ok:true`로 반환하며, quote 전환 전 action warning은 다시 살아나지 않는다. 운영 runbook은 격리 preview, 승인된 read-only Jobber schema 검증, sync maintenance/old callback drain, schema-first 반영, unresolved-operation rollback 차단을 필수 게이트로 정한다.

**남은 작업:** 단일 scoped re-review와 controller 최종 full verify, 로컬 main 병합은 완료했다. Preview의 운영 환경 공유를 해소하거나 이 브랜치의 자동 Preview 차단을 승인받은 뒤 Push·PR을 진행한다. `docs/DEPLOY.md`의 격리 preview·schema-first·maintenance/drain 게이트와 명시적 승인 후에만 운영 DB migration·앱 배포를 수행한다. 실제 Jobber mutation을 사용한 crash/reconciliation 검증은 격리된 시험 대상과 추가 승인 없이 실행하지 않는다.

**완료 기준:** 각 단계 직후 실패·프로세스 중단 및 두 세션 동시 Retry에서도 외부 line이 중복 생성되지 않는다. 외부 요청은 성공했지만 로컬 version이 바뀐 경우에도 결과를 안전하게 재대조한다.

**근거:** `supabase/migrations/20260917025111_add_jobber_durable_sync.sql`, `lib/jobber/sync-store.ts`, `lib/jobber/sync-runner.ts`, `lib/actions/jobber-sync.ts`, `components/quote-detail/jobber-sync-status.tsx`, `supabase/tests/jobber_sync_test.sql`, `tests/jobber-sync-*.test.*`.

### 3. P1-03 — Quotes 전체 집계·페이지네이션

**영향:** 최신 100건 배열로 Total/Pipeline/Average/월 필터를 계산해 `all time` 설명과 실제 범위가 다르다. 09-16 배포 기록의 활성 견적은 106건이므로 해당 기록 시점에 이미 상한을 넘었다. 이 숫자는 오늘 다시 조회한 운영 건수가 아니다.

**남은 작업:** 서버 count/sum/avg와 목록 조회를 분리하고 전체 목록 pagination을 제공한다. 금액은 Decimal 또는 DB numeric으로 집계하고, 결과 수·페이지 범위·필터 기준을 정확히 표시한다.

**완료 기준:** 100건을 넘는 fixture에서 전체/기간별 통계가 원본 데이터와 일치하고 가장 오래된 견적까지 찾을 수 있다.

**근거:** `app/(app)/quotes/page.tsx:9`, `138-161`, `181-217`; 휴지통 배포 계획 10절.

### 4. P1-02 — 가격 변경 이력의 위·변조 방지

**영향:** 활성 견적의 `quote_price_revisions`는 admin 직접 INSERT/UPDATE/DELETE와 payload의 `changed_by`를 허용한다. 정상 Server Action의 사용자 지정만으로 직접 Data API/RPC 접근을 막을 수 없다. 보안 등급은 Medium이다.

**남은 작업:** 가격 이력을 append-only로 만들고 DB에서 `auth.uid()`로 행위자를 고정한다. 감사 값도 신뢰 경계 안에서 결정한다. lifecycle 사건 표와 별개인 가격 revision의 권한을 수정해야 한다.

**완료 기준:** admin의 이력 직접 수정·삭제 및 타 사용자 actor 입력이 거부되고 정상 저장의 이력은 정확히 남는다.

**남은 작업:** input의 id/name/label/autocomplete를 지정하고 임시 비밀번호에 `new-password`를 적용한다. 고위험 작업 전에 대상·결과를 확인하고 recovery link 또는 첫 로그인 변경 흐름과 계정 작업 감사 이력을 마련한다.

## 4. P2 — 보안 보강·접근성·반복 작업 개선

### 13. P2-02 — 비운영 Jobber 토큰 암호화

### 14. P2-10 — 분산 로그인 제한·신뢰 가능한 client IP

애플리케이션 제한의 process-local Map은 인스턴스·재시작 사이에 공유되지 않는다. Hosted Supabase/Vercel의 제한을 먼저 확인하고 필요하면 공유 TTL 저장소로 보완한다. `x-forwarded-for`의 유효한 사용 방식도 호스팅 경계에서 확인한다. 인스턴스가 바뀌어도 합의한 제한이 유지되어야 한다.
